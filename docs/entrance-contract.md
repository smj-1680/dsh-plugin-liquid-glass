================================================================================
  DSH 液态玻璃插件 —— 入场动画契约（改动前必读）
================================================================================

  这份文档是**契约**，不是说明。它列出这套动画赖以成立的每条不变量，
  以及**哪些看起来无害的改动会把它悄悄弄坏**。

  改动任何与动画/闸门/z-index 相关的东西之后，请运行：

      node E:\deepseek-V4-flash\DSH-App\tools\verify-entrance-contract.js

  退出码 0 = 契约完整；1 = 有东西被碰坏了，输出里会指出是哪一条。
  校验项的编号（A1/B2/…）与本文档的章节一一对应。


================================================================================
【零】当前定稿的观感（这是"好动画"的定义，不要改坏）
================================================================================

  欢迎页（新会话页）三拍入场，块之间各错开 200ms：

      t=0ms      「探索未至之境 + 预览版」标题   滑入
      t=+200ms   工作区 / 模式 选择行            滑入
      t=+400ms   输入框                          滑入

  单块动画参数：opacity 0→1 + translateY(20px)→0，800ms，ease-out，fill=backwards

  全部可调项集中在这几个变量（在 50-glass-surfaces.css 的 :root 与
  bootstrap.js 的关键 CSS 中各有一份，两处必须一致）：

      --dsh-welcome-step            块间隔，现 200ms
      --dsh-welcome-delay-title     标题延迟，现 0ms
      --dsh-welcome-delay-row       选择行延迟，现 var(--dsh-welcome-step)
      --dsh-welcome-delay-composer  输入框延迟，现 calc(step * 2)
      --dsh-glass-enter-duration    单块时长，现 800ms
      --dsh-glass-enter-shift       位移，现 20px
      --dsh-glass-enter-ease        曲线，现 ease-out


================================================================================
【一】三道闸门，必须成对（A*、B*、D*）
================================================================================

  三个 body 类各控制一段可见性，**每个都必须同时有"隐藏"和"显示"两条规则**：

| 类 | 控制 | 隐藏 | 显示 |
|---|---|---|---|
| `.dsh-glass-ready` | 输入框 | `body:not(.dsh-glass-ready) …{opacity:0}` | `body.dsh-glass-ready …` |
| `.dsh-glass-new-session` | 转写区 | `body:not(.dsh-glass-new-session) …{opacity:0}` | `body.dsh-glass-new-session …` |
| `.dsh-glass-welcome` | 标题 / 选择行 | `body:not(.dsh-glass-welcome) …{opacity:0}` | `body.dsh-glass-welcome …` |

  ★ 只改一半 = 内容永久隐藏（或永久可见）。这是最容易犯的错。
  ★ 转写区那对**只写在 bootstrap.js 的内联关键 CSS 里**（它必须先于应用首帧生效），
    不要把它的检查挪到 50-glass-surfaces.css —— 校验项 B3 已按此约定写死。


================================================================================
【二】关键帧不能是"none"（C*）
================================================================================

  入场动画**完全由 CSS 驱动**。任何一条落在玻璃元素上的
  `animation: none` 都会让整套动画静默失效。

  ★ 曾经真的犯过：为了压掉某处的默认动画，写过
    `body.dsh-glass-ready [class*="_card"]:has([contenteditable="true"]){animation:none !important}`，
    结果把输入框的入场动画一起掐掉了（而且要加 !important 才能压过它，说明它本来就不该在那儿）。

  ★ 校验项 C1 / C2 专门守这条。


================================================================================
【三】动画必须加在"座位"上，绝不能加在玻璃上（E6、F*）
================================================================================

  输入框卡片自带 `backdrop-filter`。Chromium 对"带 backdrop-filter 且正在做
  opacity/transform 动画"的元素会提升为独立合成层，**backdrop 采样被打断** ——
  表现就是动画期间玻璃闪烁或消失。

  所以职责被拆到三个元素：

      卡片 (RlGAzG_card)   带 backdrop-filter，承载材质   —— 永不动画
      座位 (卡片的父节点)                      承载动画   —— translateY + 淡入
      闸门 (body 类)                           控制可见性

  ★ `composerSeat()` 里那句"跳过带 backdropFilter 的祖先"就是这条契约的实现，
    不要删、不要改成"第一个父节点"。


================================================================================
【四】新会话的输入框是【新节点】，必须同步打标（E7）
================================================================================

  点"新会话"（以及启动时的自动切换）时，应用把输入框整个换成新 DOM 节点。
  **新节点没有 `data-dsh-glass="composer"`** —— 而闸门正靠它。

  所以 `adoptComposerNode()` 必须在 MutationObserver 回调里**同步**执行：
  MutationObserver 回调在同一次 DOM 变更任务内运行，**早于浏览器绘制**，
  因此标记能在新节点被画出来之前落下。

  ★ 如果哪天有人把这段改成"交给扫描去处理"，你会立刻看到
    "新会话第一帧是无材质输入框" —— 那个 bug 修了很久才修好。


================================================================================
【五】三个"完成信号"的含义，别混淆（G1）
================================================================================

  启动流程里有三个不同的时刻，混用它们正是之前反复失败的原因：

  ① `startSession()` 调用成功      = 切换被【发起】，不是完成（实测还要约 1 秒）
  ② `client:composer-adopted`      = 新输入框出现 = 切换【已落地】★ 这才是判据
  ③ `client:transcript-revealed`   = 转写区揭开，同时揭开欢迎页三拍

  ★ `lib/client.js` 调完 `startSession()` 只通知"已发起"
    （`window.__dshGlassNoteSessionSwitch`），**绝不要**在那里直接揭开转写区 ——
    否则旧会话会露脸、动画会播在即将被丢弃的节点上。
    校验项 G1 会检查 `lib/client.js` 里没有出现直接揭开调用。


================================================================================
【六】玻璃层的 z-index 契约（F*）—— 与动画同一条链上的坑
================================================================================

  `#dsh-card-glass` / `.dsh-card-glass-seg` 必须是 `z-index: -1`：
  定位元素若为 0 会画在流内内容**之上**，它的 `blur(20px)` 会把相邻轮次的正文
  糊成一团（曾经表现为"怎么只渲染了一个区块"）。

  ★ 配套条件：玻璃的**宿主**必须有 `isolation: isolate`（见 `ensureGlassHost`）。
    没有它，`-1` 会让玻璃掉到宿主背景后面而**整个看不见**。
  ★ 注意 isolation 要加在【宿主】上，不是加在【内容列】上 ——
    加在列上会把列打包成一个整体，反而盖住玻璃（这个坑踩过）。


================================================================================
【七】几个容易误伤的"看起来无害"的改动
================================================================================

  1. 给玻璃元素加 `transition: opacity … !important`
     → 会和动画打架（动画期间透明度被过渡接管），表现为动画变"肉"或不动。

  2. 调 `--dsh-welcome-step` 时只改了一处
     → 50-glass-surfaces.css 与 bootstrap.js 各有一份，必须同步。

  3. 清理定时器忘了把 delay 计入
     → 代码里是 `dur + delay + 140`；不加 delay，延迟期间动画类就被摘掉，
       动画根本没机会播。

  4. 在 `revealTranscript` 里"顺手"提前揭开
     → 见【五】。它必须等切换落地。

  5. 把闸门从 "body 类 + :not()" 改成"给元素加内联 style"
     → 内联 style 会覆盖掉动画的 opacity 起点，动画直接不显示。
